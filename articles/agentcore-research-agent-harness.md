Most research-assistant demos end the same way: the model narrates what it would
compute, and nothing lands anywhere. A market analyst needs the opposite — numbers
found on the live web, checked at the source, worked into a chart and a spreadsheet
that exist. This use case builds that with a configuration instead of a codebase:
one Amazon Bedrock AgentCore harness, one prompt, three managed tools. One
invocation runs search, browser and code interpreter in the same session, leaves
`wind.xlsx` and `wind.png` in the session's VM, keeps the conversation when the
model is swapped mid-session, and exports to a runtime agent that behaves the same.
Every number below was measured in one account, `us-east-1`.

## The use case

An analyst asks a question no single page answers: how wind generation in 2024
splits across the five largest producers. Answering needs a current web index, a
way to open a source and read it, and a sandbox that turns five numbers into
shares, a chart and a file. The deliverable is a market note plus two artifacts,
produced by one prompt.

## What AgentCore does here

Four capabilities carry the use case.

- Harness: the managed agent loop. The repository ships a `harness.json` — model,
  prompt, tool list, iteration and timeout limits — and no Python loop at all.
- Browser: managed sessions for opening pages and reading their content, invoked
  directly by the harness.
- Code Interpreter: the sandbox that runs code and holds the files the agent writes.
- Observability, lightly: every tool call lands as a span in the `aws/spans` log
  group, which is where the proof of "search, browse and compute in one prompt"
  comes from.

Web Search sits outside the core nine: it enters as a gateway connector target the
harness sees as one tool.

## Requirements

- Node.js 20 or newer, the AgentCore CLI 0.31.1, AWS CLI 2.x
- A CDK app under `agentcore/cdk/` with `node_modules` installed
- Bedrock access to `deepseek.v3.2` and `amazon.nova-lite-v1:0`
- Region `us-east-1` for everything — the web-search connector only exists there
- Session ids of at least 33 characters for harness invocations

## How it works

The agent is a file, not a program:

```json
{
  "name": "research",
  "model": {
    "provider": "bedrock",
    "modelId": "deepseek.v3.2",
    "apiFormat": "converse_stream"
  },
  "tools": [
    { "type": "agentcore_browser", "name": "browser" },
    { "type": "agentcore_code_interpreter", "name": "code-interpreter" },
    { "type": "agentcore_gateway", "name": "websearch" }
  ],
  "maxIterations": 30,
  "timeoutSeconds": 900
}
```

The third tool is the gateway. Web Search is not a harness tool type; it is a
connector target on a plain MCP gateway, and the harness reaches it through the
gateway tool with no outbound auth, because the gateway itself has none. That one
indirection is what puts a managed, region-locked web index behind the same
tool-call path as everything else.

The system prompt carries facts the model cannot discover:

```text
Code interpreter sandbox facts: PIL and numpy are installed; pandas, openpyxl and
matplotlib are NOT. For a spreadsheet, build the xlsx with the standard-library
zipfile module (an xlsx is a zip of XML: [Content_Types].xml, _rels/.rels,
xl/workbook.xml, xl/_rels/workbook.xml.rels, xl/worksheets/sheet1.xml). For a
chart, draw the PNG with PIL.ImageDraw.
```

That paragraph is load-bearing. The sandbox genuinely ships no pandas, and an early
diagnostic run where the model "listed" all four packages as missing was fiction —
its `executeCode` calls had failed and it invented the result. Stating the truth in
the prompt turned six failed calls into files. The session VM is the other half:
files the agent writes stay there, and `agentcore exec` pinned to the same session
id can inspect and retrieve them.

## Deploy it

Three resources, three lines. The gateway is deliberately minimal — no authorizer,
one connector target:

```bash
agentcore add gateway --name research-gateway --protocol-type MCP --authorizer-type NONE
agentcore add gateway-target --name websearch --gateway research-gateway \
  --type connector --connector web-search
agentcore add harness --name research --model-provider bedrock --model-id deepseek.v3.2 \
  --api-format converse_stream --tools agentcore_browser,agentcore_code_interpreter \
  --system-prompt "You are a market research analyst..." --max-iterations 30 --timeout 900
```

![Terminal capture: the gateway, the web-search connector target and the harness added, one line each](/images/agentcore-research-agent-harness/D1-adds.png)

Deploy the stack — gateway, harness, and the runtime the harness runs on:

```bash
agentcore deploy -y --target default
```

![Terminal capture: the first deploy, 2 minutes 22 seconds, stack AgentCore-aiauc05-default with the harness READY at version 1](/images/agentcore-research-agent-harness/S1-deploy.png)

The harness cannot reach the gateway until the gateway has an ARN, so one more tool
add and deploy:

```bash
agentcore add tool --harness research --type agentcore_gateway --name websearch \
  --gateway research-gateway --outbound-auth none
agentcore deploy -y --target default
```

![Terminal capture: the gateway tool added to the harness, then the second deploy of 2 minutes 3 seconds](/images/agentcore-research-agent-harness/S2-gwtool.png)

Now the single invocation. The prompt asks for three steps: search 2024 wind
generation for five countries, confirm at a source page, compute shares and write
two files. It ran 4 minutes 2 seconds:

```bash
agentcore invoke --session-id research-session-0004-artifacts-run \
  --prompt "Produce a short market note on wind power. Step 1: use the websearch
  tool... Step 3: ... write two files into the sandbox: wind.xlsx ... and wind.png ..."
```

![Terminal capture: the full answer, five countries with TWh from AtlasBig and EIA, shares from 56.0 percent down to 5.1, and wind.xlsx at 1,806 bytes with wind.png at 16,705 bytes](/images/agentcore-research-agent-harness/S3-invoke.png)

"One prompt drove all three tools" is a span query away. AgentCore observability
writes spans to the `aws/spans` log group; filtering the session is two native
commands:

```bash
aws logs filter-log-events --region us-east-1 --log-group-name aws/spans \
  --start-time <epoch-ms> --query 'events[].message' --output json \
  | jq -r '.[] | fromjson? | select(."attributes"."session.id"? == "research-session-0004-artifacts-run")
    | [.name, ."attributes"."gen_ai.tool.status"] | @tsv'
```

![Terminal capture: websearch and browser spans marked success, six code_interpreter spans marked error, eleven shell spans marked success](/images/agentcore-research-agent-harness/S4-spans.png)

One `websearch___WebSearch` success, four successful browser calls — after
`Bedrock AgentCore.StartBrowserSession` — and the compute work. The six errored
`code_interpreter` spans are DeepSeek's function-call format failing to nest the
tool's dictionary input; the agent fell back to the sandbox's shell action, which
succeeded eleven times and wrote the files. The artifacts are real bytes, verified
from inside the same session:

```bash
agentcore exec --harness research --session-id research-session-0004-artifacts-run \
  -- sh -c "python3 -c \"import zipfile; z=zipfile.ZipFile('/home/wind.xlsx');
  print(z.testzip() is None, z.namelist())\" ..."
```

![Terminal capture: zip CRC check True with the five OOXML members listed, PNG magic 89504e470d0a1a0a, dimensions 800x600](/images/agentcore-research-agent-harness/S5-exec.png)

The spreadsheet passes a CRC check as a real OOXML package; the PNG carries the
correct magic and dimensions. Both files come out of the sandbox with `base64`.

The model switch is a config edit and a deploy. Change `modelId` in
`app/research/harness.json` from `deepseek.v3.2` to `amazon.nova-lite-v1:0`, deploy —
the harness moves to version 5 in 1 minute 40 seconds — and ask the same session a
question only its history can answer:

```bash
agentcore deploy -y --target default
agentcore invoke --session-id research-session-0004-artifacts-run \
  --prompt "Same session, new model. From the table you built earlier in this
  conversation: which country had the smallest share, what was the number, and what
  were the file names you wrote? Answer without searching or browsing again."
```

![Terminal capture: before the switch the answer is India at 5.1 percent, after the switch the same session answers India 5.1 percent, wind.xlsx 1,806 bytes, wind.png 16,705 bytes](/images/agentcore-research-agent-harness/S6-model-switch.png)

Identical numbers, including the byte sizes it had reported one model earlier. The
spans show why the answer is memory, not a re-run: the two chat spans share the
session, and no tool span follows the switch:

```bash
aws logs filter-log-events --region us-east-1 --log-group-name aws/spans \
  --start-time <epoch-ms> --query 'events[].message' --output json \
  | jq -r '.[] | fromjson? | select(."attributes"."session.id"? == "research-session-0004-artifacts-run") | .name'
```

![Terminal capture: chat deepseek.v3.2 and chat amazon.nova-lite-v1:0 spans adjacent in the same session with no execute_tool span after the switch](/images/agentcore-research-agent-harness/S7-spans-after.png)

The harness is portable. `agentcore export` turns the configuration into a Strands
agent — code this time, `app/researchAgent/` — which deploys to Runtime:

```bash
agentcore export harness --name research --target-agent-name researchAgent
agentcore deploy -y --target default
agentcore invoke --runtime researchAgent --session-id research-session-0007-export-same \
  --prompt "Search the web for the AtlasBig page 'wind power generation by country'
  ... Compute each country's share of the five-country total with the code
  interpreter and report the five shares to one decimal."
```

![Terminal capture: the export writing app/researchAgent and updating agentcore.json, the deploy of 2 minutes 11 seconds, and the exported agent answering 56.0, 25.4, 7.5, 6.0 and 5.1 percent](/images/agentcore-research-agent-harness/S8-export.png)

Same five shares the harness computed, from the same tool wiring. One export note
matters: the browser tool is excluded from the CodeZip export, because its Playwright
driver needs a container build.

Teardown is two stages; only both leave the account clean:

```bash
agentcore remove all -y
agentcore deploy -y --target default
agentcore status
```

![Terminal capture: schemas reset, the stack torn down in 3 minutes 12 seconds, status reporting no resources](/images/agentcore-research-agent-harness/S9-teardown.png)

`remove all -y` rewrites `agentcore/agentcore.json` and empties
`agentcore/aws-targets.json`; restore both from git before deploying again. The CDK
bootstrap stack and its asset bucket survive on purpose — account-level, reused
across this series.

## Troubleshooting

- Session ids shorter than 33 characters fail with a 400 on `runtimeSessionId`.
- The first diagnostic invoke reported every Python package missing. Its
  `executeCode` calls had all failed — DeepSeek's DSML function-call format does not
  nest the tool's dictionary input — and the model invented the result. The shell
  action of the same tool worked, and a truthful system prompt stopped the guessing.
- A contract without a CDK app aborts the first deploy with `CDK project not found`.
  `agentcore create` only works in an empty directory; generate in a temp directory,
  copy `agentcore/cdk/` in, and `npm install` inside it.
- CodeZip exports drop the browser tool (Playwright cannot run there); re-export
  with `--build Container` if the browser must come along, which needs Docker.

## Takeaways

- A managed harness is a configuration that deploys: model, prompt, tool list and
  limits in one JSON file, with no agent loop to write, host or patch.
- Web Search rides the gateway as a connector, so one region-locked managed index
  appears to the agent as an ordinary tool beside browser and code interpreter.
- Artifacts are only provable if you can reach them: `agentcore exec` pinned to the
  session id turns "the model said it wrote a file" into a CRC-checked xlsx.
- The conversation, not the model, is the session: a mid-session switch from
  DeepSeek to Nova lost nothing, because the state was never in the model.
- `agentcore export` is the exit ramp from configuration to code — same tools, same
  shares, minus the browser until you build a container.
